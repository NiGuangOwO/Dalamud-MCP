# DalamudMCP 1.0.0.12

修复 `search_item_holdings` 在雇员仓库已打开后仍一直返回“等待容器卸载/重新加载”的问题。现场确认当前客户端的雇员容器可一直保持 `IsLoaded=true`，因此该标记不适合作为雇员归属或仓库会话的依据。

现在以可见且就绪的普通/扩大雇员道具管理窗口建立所选雇员的仓库归属，每帧观察窗口关闭与雇员切换。只有对应窗口就绪时刷新雇员快照；关闭后明确返回缓存，`includeCached=false` 不会把残留缓冲区当作实时仓库。容器自身的加载标记、类型、长度和内存边界检查仍保留。

验证：Debug/Release 均为 0 警告、0 错误；ItemHoldingsTest 46/46，Release PluginLoadTest 141/141。新增回归覆盖容器常驻但窗口未打开、窗口关闭/重开后切换归属、关闭后禁止刷新快照。

原始服务器游戏内验证完成：两名雇员均可读取七页仓库、水晶和装备，共 18 个容器。第一名雇员的“冠绝之刃·回忆”读取为 1 件，含第七页在内的多个页面有实际命中；第二名雇员的“天之陶器碎片”为 16 个、“水晶龙之鳞”为 6 个。切换后第一名保持缓存、第二名为实时；关闭后两者均为缓存，数量和归属保持正确。禁用缓存时返回不可用/不完整范围；跨雇员名称检索及分页总量一致。测试仅打开和关闭管理界面，没有转移物品或修改装备、金币、价格、探险。
