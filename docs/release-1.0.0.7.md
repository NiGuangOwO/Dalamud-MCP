# DalamudMCP 1.0.0.7

普通 addon 定位可直接按标签、原生组件类型、可见/启用/可点击状态筛选，并使用 `detail=compact` 返回精简结果。筛选发生在结果数量限制之前，避免目标位于大量无关节点之后时被截断。默认完整输出保持兼容。

节点查询返回完整 `componentPath`，快照、采样、显式点击及条件点击使用同一路径在各层 ULD 中精确查找，拒绝重复 ID、不可读数据、组件所有权不符和循环路径。查询返回 `returned`、`scannedNodes`、`scanIncomplete`，明确区分筛选结果与扫描边界。路径不是生命周期令牌，窗口被替换后仍须重新查询。没有增加自动事件猜测或操作重试。

修正节点查询说明中对 `open_addon` 允许列表的错误限制，更新中英文 README、服务端指引和 Dalamud 开发技能。用法见 [addon 查询](addon-queries.md)。

验证：Debug/Release 构建均为 0 警告、0 错误；AddonQueryTest 20/20，NativeUiReadTest 55/55，ProtocolSmokeTest 50/50，实际 Release DLL 的 PluginLoadTest 132/132。原生测试包含嵌套组件路径、重复 ID、所有权、循环、深度和非法输入边界。

现场只读验证已核对运行中 Debug DLL 的 MVID；同一个 `_ActionBar` 的 320 节点，完整模式 111014 UTF-8 字节，精简模式 72795 字节（减少 34.43%）；标签 `7` 查询只返回 1 节点、414 字节（减少 99.63%），与完整结果中的对应节点路径一致，路径成功用于快照读取。更新前相同窗口的完整树为 90250 字节，过滤后相对减少 99.54%。完整模式新增路径元数据会增加输出，普通查询应显式使用精简模式与筛选。

验证没有执行游戏点击，没有测量模型内部思考时间，也未对所有 addon 布局或事件契约作保证。以上输出量来自单次现场样本，模型端是否更快应通过后续相同任务的端到端对照测量。
