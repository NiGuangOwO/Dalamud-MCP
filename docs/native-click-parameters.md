# 原生点击事件参数

`click_addon_element` 自动查找请求事件类型的注册参数时保留合法的 0。例如本次结束小游戏确认框的“是”按钮注册 `ButtonClick,param=0`。旧实现跳过所有 0，最终用默认 uint.MaxValue 替代；新实现把“找到了参数 0”和“没有找到参数”分开处理。

查询顺序：

1. 显式 `param` 仍有优先权，但必须来自已经确定的当前契约，不能用来猜回调。
2. 有请求类型的确切注册事件时，保留其原始 uint32 参数，包括 0 和 uint.MaxValue。
3. 同类型注册的参数不一致时拒绝自动派发；一致的重复参数仍可确定。
4. 没有该事件类型时保留历史回退：第一个非零参数，否则 uint.MaxValue。这只是兼容行为，不证明该事件适用于当前控件。

查找使用完整受保护的节点/事件副本，限制 64 项并拒绝不可读、循环或超限的事件链。此修复不改变 `registered` 多事件模式的语义，也不把组件事件自动改投其他接收者。下拉框、列表行、复选框等优先使用相应的明确工具。

使用前通过节点快照确认类型/参数/接收者，并核对可见性、当前 addon 与阶段。使用后检查实际结果。此次在测试构建上对结束小游戏确认框发出没有显式 `param` 的 ButtonClick，实际返回 `eventParam=0`；确认框和已通关的 Puzzle 随后关闭，客户端恢复空闲。

离线覆盖：精确 0、普通参数、uint.MaxValue、前面存在其他类型的非零事件、缺失事件回退、冲突/一致重复、无效指针和 64 项边界。
